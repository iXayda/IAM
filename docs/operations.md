# 运维指南

## 维护前提

维护命令使用与数据库及 Web 服务版本一致的 JAR，从部署环境读取连接和保护文件配置。命令独立运行，不监听 HTTP。交互命令要求真实控制台，不接受附加参数或管道输入；密码和动态码使用无回显输入。

## 持久保护文件

| 环境变量 | 内容 |
| --- | --- |
| `IAM_TOTP_KEY_FILE` | TOTP 保护文件，32 个原始二进制字节 |

保护文件限制为部署服务及授权维护人员读取，与对应数据库版本协同备份；重启不应重新生成。

## 初始化管理员

开始前完成数据库迁移，配置数据库所有者连接和持久 TOTP 保护文件。

由组织授权人员核验管理员身份，安排本人在受控终端执行：

```bash
java -jar target/iam.jar bootstrap-admin
```

按提示创建账号或选择活动账号，验证密码，绑定并验证新认证器，安全保存一次性展示的恢复码。初始化只允许完成一次，中断后可继续，完成后不能重复获取资格或恢复码。

终端不得录屏或采集秘密输出。系统成功审计证明技术事务已提交，不能证明操作者已经核验本人或凭据已送达。

## 人工核验与开通交付

组织指定管理员核对当前权威人员记录，确认不可变用户 UUID、业务归属和申请依据。高权限开通由另一名授权人员独立复核；不能仅凭用户名、能够登录的会话或本次请求新提供的联系方式认定本人。

管理员签发一次性开通凭据，交付给本人自行设置密码。使用事先登记并独立核验的组织渠道；凭据与核验记录分开保存，不进入工单正文、源码、聊天群或普通日志。组织应选定实际渠道及负责人，不由 IAM 推测可用邮箱或电话号码。

原申请记录关联核验人、依据类型、批准人、用户 UUID、操作关联 UUID、交付时间及结果，不附身份证明副本、密码或单次凭据。交付失败时先核查提交状态，再取消或重新签发；通知失败不通过回退已提交事务处理。
