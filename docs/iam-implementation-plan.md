# IAM 研发实施计划

## 1. 实施目标与内容

为单个组织的多个自有应用建立统一的身份与访问管理能力，完成账号、登录、应用授权、会话管理和安全审计的完整流程，提供 JVM 与原生运行方式及配套交付材料。

| 工作项 | 交付内容 |
| --- | --- |
| 用户与凭据 | 本地用户创建、资料修改、查询、搜索分页、启用与禁用；稳定且不可变、不复用的身份标识；用户查看本人资料；受控开通、密码登录、改密及经过身份核验的恢复流程 |
| 管理入口 | 管理员受控初始化、TOTP 与单次恢复码、因素注册和更换、受控恢复、固定管理权限、敏感操作验证及最后可用管理入口保护 |
| 协议与接入 | 保密 Web/BFF 客户端的 OIDC 授权码与 PKCE S256；Discovery、JWKS、Token、ID Token、基础 UserInfo；两个独立应用的登录与 SSO |
| 客户端管理 | 客户端创建、查询、修改与禁用；配置精确回调地址、scope、资源 audience 及允许角色；客户端秘密安全生成、保存、一次性交付与更新 |
| 应用授权 | 资源、角色及用户绑定的管理和查询；按目标资源及客户端允许范围投影角色；由接入应用在服务端逐请求执行具体业务权限及所有权校验 |
| 授权生命周期 | 浏览器会话与应用授权的查看、当前退出、指定撤销、全部下线及管理员强制下线；闲置与绝对期限；Refresh Token 轮换、重放处理及资源在线状态校验 |
| 审计与运行 | 核心安全事件记录、受权限保护的过滤与分页查询；持久密钥、正常轮换与失陷处理；受限运行身份、健康检查、安装、备份与恢复 |
| 接入说明 | OpenAPI 规范与独立预览工具、独立身份前端的接入约定、应用接入示例及必要使用说明 |
| 构建与交付 | 可执行 JAR、原生程序及所需共享库、JVM 与原生容器、Compose 配置和环境变量示例；源码、安装维护材料、构建来源、校验摘要及项目与第三方许可声明 |
| 自动化验证 | Java 测试、真实数据库与 HTTP 验证、应用示例检查、JVM 与原生服务的浏览器验证、容器配置检查及发行产物核对 |

## 2. 技术路线与依赖

- 采用 Java 21、Spring Boot、受维护的 Spring 官方 OAuth/OIDC 组件及 PostgreSQL，先验证版本兼容性、持久化扩展点、密钥接入和并发语义。
- 精确依赖版本在路线验证时根据实际可用且受维护的版本确定；后续升级与适配、验证同步提交。
- IAM 后端采用单个 Web 实例和独立数据库，按技术层组织代码，明确生产代码、示例与测试的目录边界。用户登录及管理交互由独立身份前端负责，本仓库提供认证、管理和协议接口，维护接入约定并验证前后端交互。
- 可执行 JAR 提供 Web 服务及离线维护命令；GraalVM 原生程序仅提供 Web 服务，维护使用同版本 JAR。验证 AOT、运行提示、资源和安全组件的兼容性，保持构建时确定的 Spring profiles 与运行配置一致。
- 提供 JVM 与原生容器，通过 Compose 和环境变量配置运行连接与入口；容器采用非 root 身份、只读文件系统和最小权限，证书及持久保护密钥与通用镜像分离。原生发行包与镜像归档面向 Linux amd64，并声明所需系统及共享库条件。
- 浏览器和协议公开入口使用 HTTPS，可由 IAM 或受信代理终止 TLS；HTTP 回源仅用于受保护网络，限制代理来源，默认不信任转发头。issuer 使用显式配置的固定 HTTPS 地址。
- 使用全新空库；原型、安装和恢复验证均使用隔离数据库。
- 账号开通和用户恢复采用管理员核验身份、签发用途隔离的单次证明及受控人工交付；证明消费后通过正常认证登录。真实核验人员与渠道由组织提供。
- 管理员采用 TOTP 与恢复码，使用同源后端会话；恢复只授予因素重建能力，完成新因素验证前不授予管理权限。唯一管理员失去因素及恢复码时采用独立、可审计的部署恢复流程。TOTP 不具备抗钓鱼能力。
- 自有应用采用管理员预授权、直接用户—资源角色绑定；保密客户端使用 `client_secret_basic`，允许的 scope 为 `openid`、`profile`、`offline_access` 的受控子集，不因新增范围扩大已有授权。
- 资源默认严格验签并使用绑定单个资源的受限身份调用 Introspection；正缓存最多 5 秒且不超过 Token 有效期，管理权限不缓存，在线依赖故障时拒绝新的受保护操作。
- Access Token 与 ID Token 最长有效期为 300 秒，验签时钟偏差最多 30 秒；离线资源须明确接受最长 330 秒的撤销窗口，不能在在线故障时自动切换为离线放行。
- 在对应功能开放前明确其余会话与凭据期限、限速参数、秘密保护及故障处理规则，随实现记录并验证；部署参数调整不能削弱既定安全要求。
- 接口、数据模型、行为参数和事务锁协议与对应实现一起确定，通过约束及并发验证后交付。
- OpenAPI 随接口维护，覆盖控制器及安全过滤器处理的端点；通过受保护入口导出规范，使用独立工具预览。身份前端由接入方实现，仓库内前端夹具仅用于验证接入契约。
- 持续集成覆盖 Java、应用示例、JVM 与原生服务的浏览器交互及容器配置；独立任务合理并行，依赖构建产物的验证复用同一产物，统一汇总必要检查。发行产物关联同一源码提交，附来源信息、校验摘要和许可材料。

## 3. 实施步骤

| 步骤 | 主要交付 | 验收依据 |
| --- | --- | --- |
| P0 路线与环境验证 | 构建入口、依赖版本、隔离环境及协议持久化关键风险验证 | 版本兼容性明确；关键扩展点具有可复现验证方法；未解决风险列明 |
| P1 身份与安全基础 | 用户管理、数据约束、公共安全控制、管理员 TOTP 与恢复码、开通恢复、审计记录与查询及受保护管理入口 | 身份唯一性、凭据单次消费、因素管理与恢复、权限隔离、最后管理入口保护、CSRF 和审计通过真实数据库及 HTTP 验证 |
| P2 应用授权基础 | 持久签名密钥、资源及角色管理、直接用户角色绑定、保密客户端管理及资源校验身份 | 配置约束、范围与所有权、秘密保护、敏感操作及权限隔离通过验证，为协议接入提供可校验的授权目录 |
| P3 协议与授权生命周期 | 持久协议状态、密钥适配、Discovery/JWKS/Token/ID Token/UserInfo、角色投影、会话管理、刷新轮换、Introspection 及安全变更撤销 | 正常登录、非法回调、PKCE、state/nonce、跨客户端兑换、授权码及刷新重放、跨资源隔离、并发状态变化和重启行为通过验证；在线与离线撤销窗口分别验证 |
| P4 接入契约与端到端验证 | OpenAPI、独立身份前端接入约定与测试夹具、两个独立 Web/BFF 和资源服务示例 | 以真实浏览器验证登录与 SSO、资料、开通、MFA、恢复、客户端与角色管理、会话操作及越权和 CSRF 拒绝；核对敏感操作及秘密展示清理约定 |
| P5 运行与交付 | 受限数据库身份、安装配置、健康检查、密钥生命周期、备份恢复、JVM 与原生运行、容器、持续集成及发行材料 | 隔离空库安装、角色权限、依赖故障、密钥轮换、失陷处理和恢复验证通过；JVM 与原生服务通过真实交互验证；容器配置、镜像构建及归档加载通过检查 |
| P6 总体验收 | 同一源码提交的构建与验证、发行产物清单、来源及校验信息 | 功能和失败场景具有对应构建的完整验证证据；发行产物与许可材料齐全，校验摘要一致；隔离环境结果与实际部署前置输入分别核对 |

按依赖顺序推进，可围绕已有能力迭代；步骤不对应固定提交数量。CSRF、敏感操作验证和审计等前置能力随首次使用它们的功能交付，端到端验证步骤不推迟这些安全能力的实现。

每个增量携带必要声明、配置、数据约束、测试及说明，保持已有链路可运行；接口契约与接入约定随首次实现同步维护，持续集成随对应验证能力接入。

## 4. 验收标准

- 用户与管理员保持独立授权边界，普通应用角色不能授予 IAM 管理权限；管理员完成 MFA 后获得管理权限，敏感操作验证与目标绑定。
- 登录标识具有明确的规范化与唯一性规则；用户资料及会话操作校验所有权，用户不能读取或修改其他用户私有资料；分页不能限制批量撤销或管理员保护的完整性。
- 每个管理接口按当前权限授权；并发管理操作不能移除最后可用入口。新因素验证后才激活，TOTP 和恢复码拒绝重放，恢复不得绕过 MFA 或重新开放已完成的初始化入口。
- 密码使用 Argon2id 和弱密码检查；单因素密码至少 15 个字符，支持至少 64 个字符及空格，不强制无依据的周期改密与字符组合；登录及凭据入口按账号与来源执行统一失败响应及限速，限制请求大小和异常输入。
- 单次证明绑定账号与用途，过期、重放、取消、错绑及被替换的旧证明均不能使用；未完成开通的账号不能获得普通应用授权，证明仅在有效提交时消费。
- 授权码绑定客户端、精确回调地址及 PKCE；客户端校验 state，携带 nonce 时保持绑定与验证；协议请求、错误、Discovery 和实际能力一致。
- 资源校验 Access Token 的签名、允许算法、密钥归属、issuer、audience、期限及用途；ID Token 不能作为业务 API 访问凭据；UserInfo 按实际获授 scope 投影资料。
- 客户端不能扩大配置允许的 scope、audience 或角色，禁用与关键配置变化按约定撤销授权；客户端秘密不在查询中返回，业务 Token 不携带管理权限。
- 刷新凭据与主体、客户端、授权及范围绑定；同一父凭据最多产生一个有效后继，刷新不扩大权限或延长家族绝对寿命；重放撤销对应家族及应用授权，并保留有效检测窗口内的已用摘要。
- 明确区分 IAM 浏览器会话、应用授权和业务应用本地会话；验证会话固定防护、闲置及绝对超时、当前退出、指定撤销和全部下线的各自效果。
- 浏览器和协议公开入口使用 HTTPS，分别验证 IAM 终止 TLS 及受信代理终止 TLS 的配置；HTTP 回源限制代理访问，不采信不受信来源的转发头，issuer 不从请求头推导。Cookie 配置 Secure、HttpOnly、SameSite 及适当作用域；Cookie 写操作具有 CSRF 防护，安全响应头与敏感响应缓存策略适当。
- 密码、完整 Token、证明、恢复码、因素秘密及私钥不进入日志、审计或普通资料响应；证明领取页面清理 URL 中的秘密，必要交付页面只展示一次。
- 禁用、改密、恢复、角色及客户端变更与并发认证、授权、刷新保持一致；等待锁后复核状态与期限，旧授权的失效符合约定窗口。
- 成功安全变更与成功审计原子提交；刷新重放的撤销与失败审计原子提交，其他失败具有明确的持久化及故障处理规则。
- 审计覆盖认证成功与失败、限速、授权拒绝、账号与凭据、因素、会话、角色、客户端及密钥变更；记录操作者、目标、结果、时间及关联标识，支持受权限保护的过滤与分页查询，防止未授权修改。必需审计不可用时拒绝相应请求并报告降级。
- 签名密钥重启后状态不变；正常轮换保留必要旧公钥，失陷立即停止签发并撤销受影响授权；在线校验拒绝失陷密钥，离线资源具有明确的紧急更新与剩余风险窗口。
- 数据库与对应加密密钥协同备份恢复；恢复后撤销旧会话、授权、单次证明及管理员恢复码，防止旧快照复活已消费凭据、失陷密钥或已关闭的初始化入口；无法核实安全状态时停止相关签发或保持主体禁用。
- 使用真实数据库验证唯一性、单次消费、回滚和并发；使用独立客户端及真实浏览器验证登录、SSO、权限隔离、退出和凭据交互。
- OpenAPI 与实际接口及错误响应一致，导出与预览可用；独立前端接入约定通过测试夹具验证，不将测试页面作为产品前端交付。
- JVM 与原生程序分别通过真实数据库、浏览器和协议交互验证；原生构建覆盖常规运行及启用文档的配置，并核对必要 AOT 元数据、共享库和运行条件。数据库安装与维护通过同版本 JAR 验证。
- 容器构建定义与 Compose 配置有效，镜像采用受限运行身份并保留必要许可文件；验证镜像构建、归档和重新加载的一致性。存活与就绪探针正确反映进程及必要依赖状态。
- 持续集成检查失败时阻止发行材料组装；核对同一源码提交的 JAR、原生包、源码包和镜像归档，保留构建来源及项目和第三方许可，验证校验摘要与实际产物一致。
- 同时验证正常路径、无效凭据、重放、越权及依赖故障，测试报告不得以跳过代替通过。
- 在隔离环境验证重启、密钥轮换和备份恢复，核对身份、安全状态、审计缺口及实际恢复耗时。
- 交付前执行完整验证并关联同一源码构建；文档、源码存在或局部测试通过不能代替总体验收，隔离环境验收不替代真实部署条件的确认。

## 5. 待确认输入

| 输入 | 用途与确认时点 |
| --- | --- |
| 身份核验与交付责任 | 确定核验人员、依据、可信渠道和交付失败处理；生产开通及恢复流程投入使用前确认 |
| 唯一管理员紧急恢复 | 确定恢复责任人、授权依据、秘密交付和审计要求；生产启用前确认 |
| 容量与网络 | 提供用户规模、并发、硬件、代理和网络条件，用于校准密码哈希、限速及数据库配置；生产容量验收前确认 |
| HTTPS 与应用接入 | 确定 issuer、域名、真实应用及回调地址；生产接入验证前确认 |
| 资源校验接入条件 | 确认真实资源是否接受既定在线依赖及最多 5 秒缓存；离线资源须明确接受最长 330 秒撤销窗口，并确定失陷密钥紧急更新流程；真实资源接入前确认 |
| 审计与恢复目标 | 确定组织批准的保留要求、RPO/RTO、备份材料和保管责任；生产恢复及保留策略验收前确认 |

真实部署输入未确定时，使用明确的测试身份、测试应用和隔离环境验证；生产容量、恢复流程及保留策略按各自确认结果验收。
